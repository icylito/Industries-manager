HOW I GRADE
- Against the REAL running app: Angular dev server + throwaway API (port 5005, throwaway DB), signed in as
  admin, Chrome via the browser tools, DevTools console and network log open. Plus ng test, ng build,
  dotnet build, the python checks and direct HTTP calls. The coder's notes, commit messages and claims
  count for nothing until I reproduce them.
- 100 points in 7 sections, divided by 10 for the score. Within a section each line is all or nothing
  unless it says otherwise. A thing I cannot run (missing, crashes, blocked) scores 0, not "probably fine".
- Caps (at the end) are applied after the sum; the lowest cap wins.
- Each loop is graded fresh; a fix that breaks something that passed before loses that line again.

    view does not move. Also: focus a note, pan with Space+drag, Ctrl+Z: removes the last real edit,

B2  Undo drops a carried snapshot. Carry the circle on the Overview, go to the Scratchpad, place a note,

    (discard N changes)" shows the right N (4); "Keep mine as a new board" creates a board whose content
    is tab B's 4 edits, and tab A's board is untouched. Nothing overwritten without a choice.
B5  Carry during an in-flight save. Delay PUTs 1500 ms, edit the board, immediately carry from the tray
    path (or carry in another tab). Pass: no "Couldn't carry" toast, undo stack and selection intact.
B6  load() leaves stale state. Open board A, make an edit, switch to board B before the save fires,
    switch back. Pass: A's edit saved to A (never to B), B's undo stack empty on open, no stray timer

B7  Note text starts a drag. Click and drag inside a note's text to select words. Pass: text selected,
    note does not move, no undo step.
B8  Pan/wheel re-PUTs the document. Pan and wheel-zoom for 10 s. Pass: zero PUT /boards/{id}; at most a
    throttled (~2 s) PATCH of the view; reload restores the view.
B9  Periodic save owned by the page. Code check: the 2-minute timer lives in the engine/sync, not in
    scratchpad.ts. Run: leave the page idle 5 min with nothing unsaved: zero requests; navigate away and
    back: exactly one timer, not two (no doubled PUTs).
B10 crossings() centre-to-centre. Unit test or console: a line between two cards whose centre line
    crosses a third card but whose edge-to-edge path does not (and vice versa). Pass: crossings uses the
    same linePath as the renderer; a test proves it.
B11 `at` centre vs top-left. Place every kind with placement 'auto' and at a drop point. Pass: each
    lands centred on the drop point; no overlap with existing items; no hardcoded {w:236,h:92} in the page

API (3.5): by HTTP against 5005, each refusal must be a 400 with a plain message and nothing stored:

SECTION 2. ARCHITECTURE (15 points)
Checked by reading the code and running the tests, then poking at the seams.
-----------------------------------------------------------------------------------------------------
A1 (3) One entry point changes the board. Every board mutation goes through engine apply/Tx/amend/setView.
   grep: no structuredClone + history push outside the engine; no component writes doc signals directly.
   One user action = one undo step (spot-check 10 actions).
A2 (2) Public begin/end/live, commit, textLive, moveManyLive, startAutoSave/stopAutoSave and the page
   pass-throughs listed in the plan are gone (grep finds none). The 7 begin/end sites use Tx; a Tx
   left open on Esc or pointercancel is cancelled (test it: press Esc mid-drag, item returns, no step).
A3 (2) Discriminated union in models/board.ts; BoardDocument has no view, no tray. KINDS registry drives
   size/minSize/caps/bar; switch(item.type) sites in the page and template mostly gone (count before 20+,
   after: a handful at most, each justified). Template uses data-kind, not 7 class bindings.
A4 (3) geometry.ts and tools.ts import nothing from Angular or the DOM; specs exist for bounds, world/screen
   round trip, edgePoint, linePath, crossings, place, intersects, simplify, and for tool gestures (drag,
   box select, pan, line, pen, rect, resize, Alt-duplicate) with a synthetic PointerCtx. The 5 hand bounds
   and 5 conversions (incl. note-editor.ts) are replaced.
A5 (2) Page onPointerDown/Move/Up are a router over hitTest + Tool; the Drag interface is gone; one
   isEditable() used by pointer and key code. scratchpad.ts is clearly smaller than 866 lines.
A6 (2) API: per-type validator table (dictionary by type) replaces the item loop; one /scratchpad route
   group; DatabaseReady.WaitAsync shared by the sweepers.
A7 (1) Per-user lock: TakeAsync(AppLock, int scope) with pg_advisory_lock(int,int) used by boards, tray
   and sweep.

SECTION 7. STRESS (10 points, 2 each)
-----------------------------------------------------------------------------------------------------
S1 500 items (scripted via the page or API): opens < 3 s, drag/pan stays usable (no multi-second freeze),
   box select all + move + undo works, saves under the server caps.
S2 50k stroke points across strokes: drawing a long stroke stays smooth; the cap stops collection with a
   plain note rather than a refusal on save; board saves and reloads identical.
S3 Key bursts: hold an arrow 5 s, mash Ctrl+Z/Ctrl+Y 50 times, N x30 fast: one undo step per burst/press as
   designed, no stuck Tx, no duplicate ids, pill ends at Saved with few requests.
S4 Two tabs on one board, editing alternately for 2 minutes: every 409 surfaces the choice; no silent
   overwrite either way; final server document equals what the chosen tab shows.
S5 Slow API (window.fetch wrapped to delay 1500 ms) and API down (stop the process mid-edit, restart):
   page stays usable, pill truthful throughout, no lost edits after recovery, no unbounded retry storm
   (count requests over 60 s), switching boards while slow does not mix documents.

CAPS (applied after the sum; the lowest applies)
-----------------------------------------------------------------------------------------------------
- Any silent data loss (an edit, board, tray chip, setting or file gone without the person choosing it,
  including a sweep deleting a referenced file, or a save landing on the wrong board): max 4.
- "Saved" shown while the server does not hold the latest change: max 5.
- Migration applied to the real database before the user saw Up, Down and SQL, or check_migration.py
  not passing with the Down fixture: max 5.
- Another person's board, tray, file or settings readable or writable: max 3.
- Ctrl+Z missing or broken for any shipped action type (the user's "essential"): max 6.
- App fails to build, ng test red, or the page fails to load: max 3.
- Any uncaught console error during normal use of the Scratchpad: max 7.
- Sideways scroll or unusable layout at 390 px on any admin page: max 7.
- Architecture claims false (public begin/end/live still used, or a second mutation path outside the
  engine): max 7.
- A listed bug (1-11) still reproducible: max 8 for one, max 6 for two or more.
- Coder claims a check passed that I find failing: minus 1 per false claim, after caps.
